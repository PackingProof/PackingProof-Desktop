# 京东双条码识别约定

电脑端与手机端使用同一规则：复用当前帧查找，不为京东额外等待下一帧。

## 规则

- 首先按各端已有候选排序选择有效条码（电脑端中心距离优先，手机端面积优先）
- 首选为京东裸号时，在同帧其余有效候选中寻找同一运单的合法包裹号，多个匹配继续使用原排序
- 单包裹 `-1-1-` 去掉后缀，多包裹如 `-1-2-`、`-2-2-` 保留完整包裹号
- 首选已经是包裹号时直接处理；没有对应包裹号时返回裸号
- 桌面快速解码只得到裸号时继续当前图像的已有慢速解码；不切换到无关订单
- 后缀必须包含末尾横线，序号和总数为无前导零的正整数，序号不大于总数，数值不超过 2147483647
- 当前只启用已确认的 JD + 数字、JDVA + 数字，裸号长度 8–40，完整包裹号不超过 40；未确认前缀保持原样，现有用户单号校验仍生效
- 在稳定识别、去重和录制决策之前输出最终单号；单包裹的两种码不能绕过既有重复触发保护
- 无图像输入只做单包裹归一化，不执行同帧查找

## 边界

不新增跨帧身份关联，不给已有录像补改单号，不迁移数据库或修改上传协议。某帧只解出裸号、后续帧才解出多包裹号时，仍按现有录制规则处理。

## 回归

两端 JdBarcodePolicy 测试保留相同的归一化样例，覆盖 JD/JDVA、单包裹、多包裹、缺少末尾横线、非法序号、溢出及非京东单号。另测同帧裸号优先、包裹号优先、无匹配回退、不同运单不配对、不同包裹不合并及持续可见不重复确认。
